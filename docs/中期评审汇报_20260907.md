## 二、陈庚泉：数据库端 + 充电站管理（已完成，已合入 main）（约 1 分半）

谢谢组长。我汇报两块：数据库端和充电站管理，这两块已经合入主干。

数据库这边，我按需求矩阵 NO.14 和 NO.15 设计了 8 张表：用户、充电站、充电桩、充电订单、管理员五类核心表，再加上支撑两个创新点的营销策略表、电桩健康阈值表和功率日志表。（展示：src/database/schema.sql 代码页，或 sqlite3 打开数据库后的 .tables 列表）建表脚本 schema.sql 统一放在仓库，服务器端启动时自动执行建库，保证每个人拿到的表结构一致。设计上做了三件事：主外键和唯一约束保证数据一致性；金额按“分”存储，避免浮点误差；加了一致性触发器和性能索引。这块配套了 11 个数据库契约测试，全部通过。

充电站管理对应需求矩阵 NO.12，我实现了完整闭环：充电站列表，显示电站名称、地址、经纬度、总桩数、在线率；（展示：运行中的 PcServer 充电站列表窗口）点进电站能看到站内每一根电桩的实时状态，我们做了 3 秒一次的模拟刷新，让在线率跟着动态变化；（展示：点击电站行 → 站内电桩明细窗口，等 3 秒看在线率/状态变化）另外支持新增电站，会按填写数量自动生成模拟电桩。（展示：新增电站对话框 → 填写并确认 → 列表出现新电站）数据访问层和界面层分离，数据层叫 StationStore，全部用参数化查询，没有拼接 SQL 的风险。（展示：stationstore.cpp 中 prepare/bindValue 代码片段）整个模块的自动化测试是 32 个，包括数据库、数据访问和界面三个层面，全部通过。（展示：运行 tst_schema/tst_stationstore/tst_stationui，终端显示 Totals: 通过）
