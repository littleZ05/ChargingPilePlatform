# 重构测试方案

## 范围与结果口径

覆盖需求 NO.1–23，按需求矩阵追踪实现、自动化和人工验收。该文档正在随迭代补齐；测试通过仅证明其覆盖范围，不代替在线地图、桌面操作或最终交付验收。

## 自动化入口

`python3 tools/verify.py` 独立构建两个应用和所有测试工程；`--filter 文件名.pro` 聚焦单模块。每个项目保留 verify.log、JUnit XML；整体 JSON 记录提交、是否有未提交修改、退出码和耗时。任一失败返回非零状态。

测试使用临时数据，不运行默认重置业务库的演示脚本。构建产物不提交。增量资源依赖需验证 schema.sql 修改后实际重新嵌入资源；源目录旧 .moc 文件应移出以免遮蔽生成结果。

## 桌面与在线验收

- 用新用户完整执行建单、等待、结算；比对客户端余额、后台营收和大屏营收。
- 充电时关闭客户端再登录，检查强制恢复；余额不足时充值再结算。
- 修改昵称、上传图片，退出再登录核对持久化；错误图片需有提示。
- 设置有效地图Key，定位地址，分别执行驾车与步行路线；核对起终点、内嵌页面和备用浏览器。断网后提示失败，恢复网络可重试。
- 大屏断网/恢复、无数据/有数据、窗口缩放和中文显示需截图或录屏留证。
- 预测1/6/24小时、推荐、工作线程和阈值计算测试待后续模块实现后记录具体入口，不能提前标完成。

## 预测迭代新增验证

- forecast_async_tests：记录计算线程ID，验证不在主线程执行，提交后修改原输入不影响快照。
- loadforecast_tests：24小时输出、近期样本选取；使用合成线性时序按时间留出24小时比较OLS、WMA和最后值基线，不混用训练/未来数据。
- loadforecastdata_tests：同桩小时内重复样本不成倍增加功率；真实零值被视为有效观测。
- services_tests：无真实预测时不打折、有足够零负荷记录时可打折；阈值样本不足时保留旧值，故障状态拒绝校准。
- station_recommendation_tests：默认距离排序、低拥堵排序、缺失预测退后、服务器空列表显示为空。

功率记录目前按“每桩小时均值，再按站求和”聚合，属于简化采样估计；未知时间段与缺测插补仍需最终口径审核。天气、节假日和真实站点误差评估尚未作为已验收功能。
