# 创新点2：异常检测“自愈”告警设计（NO.23）

> 负责人：张芮萌（自愈检查定时任务）；接口依赖：吴羽桐（ML 阈值计算）、陈庚泉（表结构）
> 规则常量：`src/common/common.h` → `cp::SelfHeal`；分级：`cp::HealLevel`

## 业务规则

1. 数据库记录每次充电结束后的**实际功率**（`pile_power_logs`）；
2. ML（简化统计过程控制：移动平均极差法，吴羽桐）离线计算每根桩的正常波动阈值，写入 `pile_health_metrics`（avg_power/low_threshold/high_threshold）；
3. PC 服务器端启动“自愈检查”定时任务（QTimer，周期 `kCheckIntervalSec`）：
   - 实时上报功率连续 `kConsecutiveCount` 次低于历史均值 `kLowPowerRatio`（20%）→ 状态置 `Warning(需检查)`，自动发送一条模拟“远程重启”指令；
   - 重启后恢复正常 → `Normal`；仍未恢复 → `Fault`。

## 状态机

```
Normal ──连续3次功率低于均值20%──▶ Warning（自动模拟远程重启）
  ▲                                  │
  └──────── 功率恢复正常 ◀───────────┘
  Warning ──重启后仍异常──▶ Fault（人工介入）
```

## 表结构对应（schema.sql 已含）

- `pile_power_logs(pile_id, order_id, real_power, logged_at)`：实功率数据源；
- `pile_health_metrics(pile_id, avg_power, low_threshold, high_threshold, sample_count, updated_at)`：阈值表；
- 服务器端检查逻辑与“充电桩管理”的远程重启（毛悦琮模块）联动：正常人工重启保留，自愈为自动触发。

## 接口约定草案（待吴羽桐确认）

- 吴羽桐 ML 端提供：根据 `pile_power_logs` 批量计算阈值并写 `pile_health_metrics`（可为独立小工具/脚本）；
- 张芮萌服务器端提供：`SelfHealChecker`（QTimer 驱动）读取实时功率与阈值，输出 `HealLevel`；
- 实时功率来源：Socket 上报（吴羽桐通信组件）或演示数据模拟。
