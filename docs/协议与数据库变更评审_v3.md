# 订单与资料协议 v3 变更评审

授权：组长 littleZ05 于本次任务明确授权跨模块重构、自主审核和合并。此次由同一维护账号承担协议与数据库评审；不冒用其他成员签名，不向群聊发送消息。

## 契约

保留 CP + 2 字节类型 + 4 字节长度帧头与既有消息类型编号。登录成功后连接绑定手机号；未登录写操作返回 401，请求 phone 与绑定身份不同返回 403。手机号免密是课程约定。

写操作 4/2/5/7/30 要求 request_id（1–80 字符），客户端使用 UUID。相同用户、编号、类型、内容重试返回持久化成功回执；同编号不同内容返回 409。业务效果和回执在同一 SQLite 写事务提交。失败回滚，不持久化成功回执。结算另以订单状态防止不同请求编号重复扣费。

- 4：pile_code；返回 order_id、start_time、power_kw、unit_price 等。
- 2/5：order_id、kwh，可选 pile_code；服务器按订单归属和开单价结算。故障或冻结不阻断既有订单合理结算。
- 6：返回昵称、头像、余额、最近100单、active_order。恢复必须使用这里的最新订单，不能用旧建单回执重启计时。
- 7：nickname 或 avatar（base64图片）；服务端限尺寸并重编码256像素PNG，作为受控内容保存在既有 avatar_path 列；此列不再解释为客户端路径。
- 30：amount，正数、最多两位小数、上限100000元；模拟支付，真实更新余额。

本次不兼容缺少身份/请求编号的旧写客户端。服务端和用户端必须一起构建发布；读取与心跳保持兼容，不能为兼容旧客户端开放匿名写入口。

## 数据库

新增 request_receipts 和 selfheal_cursors（持久化自愈样本游标）；增加“一用户一活动订单”“一桩一活动订单”部分唯一索引。金额继续以元存储，最终金额和余额舍入到分，开单单价保留精度。

建表、补列、索引与 user_version=3 均在事务中执行。旧库含冲突订单时拒绝升级且整体回滚，原订单不自动删除或取消。发布前停止程序并备份数据库；冲突需按真实订单核对后处理，禁止用重置演示库代替迁移。

## 评审证据

charge_service_tests 验证身份隔离、活动订单限制、价格快照、重启后重复请求、余额不足回滚、回执写入失败回滚、旧结算不能影响新订单、资料持久化、无效图片回滚、冻结策略、电量边界，以及冲突迁移不改变旧库。真实 TCP 集成另验证会话绑定与拒绝路径。最终合并前需完成客户端恢复/回包丢失测试和全量回归。

自愈补充：游标、状态和事件在同一事务提交；预警时保存 sample_id，故障升级要求该编号之后的三条低功率样本。服务重启、重复扫描、单条追加都不能复用历史数据升级。活动订单保持 state=1；health_level=2 禁止新订单。新正常样本解除自愈故障；事件写入失败回滚游标及状态，且不发成功信号。
