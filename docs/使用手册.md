# 使用手册

本文随重构迭代更新。当前覆盖已实现的订单/用户资料与导航功能；最终发布版本、完整安装验证和其他模块说明仍待交付验收补齐。

## 环境与构建

Ubuntu 22.04、Qt 6.2.4；依赖 Widgets、Network、Sql、Charts、WebEngineWidgets 和 SQLite 驱动。使用 qmake6 和 make。WebEngineWidgets 是导航内嵌网页新增依赖，缺少时需安装 qt6-webengine-dev。

```bash
cd /home/bit/桌面/dongruan_ws/ChargingPilePlatform
python3 tools/verify.py
```

命令会构建服务端、用户端和测试工程，输出保存在 `build-verification/`。主程序分别在 `src__pcserver__pcserver/PcServer` 与 `src__userclient__userclient/UserClient` 子目录。测试采用独立数据库和应用配置目录。

## 启动与账户

先在图形桌面终端运行 PcServer，再运行 UserClient。管理员为 admin / 123456；用户输入11位手机号免密登录，未注册自动注册并获得100元演示余额。

服务端默认数据库在可执行程序旁边，可用 `PCSERVER_DB_PATH` 指定。先停止程序再备份库，服务端与客户端须同时升级。旧库含同用户或同桩的多个活动订单时，升级拒绝并回滚，不会自动删除订单；需要按实际业务核对冲突。

## 充电与结算

1. 登录后选择充电站、正常空闲电桩，发起充电。
2. 服务器确认建单并锁定本单单价后开始计时。电量按功率和时长模拟。
3. 点击结束并结算，界面显示待确认；只有服务器成功回执后显示结算结果。
4. 余额不足时去“我的”充值，然后返回重试结算。充值为模拟支付，余额写入数据库。
5. 断线或关闭后重新登录，系统恢复未完成订单并引导结算。同用户不能同时另开活动订单。
6. 请求结果不确定时，重连会用原请求编号核实结果，避免重复扣费。

已有订单允许在账号冻结或电桩健康故障后合理结算；冻结用户和异常电桩不能新建订单。充电中折扣变化不改变该单已经确认的价格。

## 用户资料

在“我的”编辑昵称，等待服务器保存结果。头像选择 PNG/JPEG 图片，尺寸不超过2048像素；服务器验证并缩放保存。重新登录可读取已保存资料及近期订单。客户端绝对文件路径不会作为共享头像路径发送。

## 地图导航

在首页定位并选择目标站，进入导航页。顶部选择驾车或步行，预览路线后点击“打开腾讯地图导航”，在应用内网页查看规划；“在浏览器打开”作为备用入口。

腾讯地图网络请求需要网络及适用的 `TENCENT_MAP_KEY`。网络失败时静态预览和网页可能不可用，直线估算会明确标记为估算，不代表实际道路路线。坐标异常时先重新定位。

## 自愈告警

自愈检测会记录最近已处理样本；三条低功率记录触发预警和模拟重启，之后再出现三条新异常样本才升级故障。重复扫描或服务重启不会把旧样本算作新证据。新正常样本解除自愈故障。

这是模拟运维，未向物理电桩发送重启指令。检测不会释放仍有活动订单的桩。演示注入按钮用于演示样本，不能作为真实设备采集证据。

## 预测、推荐与阈值校准

负荷预测页可选择未来1、3、6、24小时，计算在后台线程执行；切换站点或模型后，旧计算结果不会覆盖新选择。峰值达到容量80%时显示运营预警。

首页默认距离优先，可切换“低拥堵推荐（未来1小时）”。预计空闲桩数按预测功率占额定容量的比例估算，不是排队或预约承诺。缺少有效功率记录时不参与预测推荐，定价维持基础价；演示曲线仅用于图表展示。

在自愈页选择正常电桩，点击“重算正常阈值”。系统读取最近100条功率记录、剔除已知异常及离群值，至少保留6条才保存。低功率阈值为正常均值的80%，高控制限按相邻样本移动极差估计；高控制限目前用于记录，自动告警仍按连续低功率规则执行。出现预警或故障时应先排查，不能直接重算阈值掩盖异常。

缺测说明：历史窗口内部缺测小时采用线性插补，窗口两端沿用最近的实测值；实测零功率保留为零。图表显示插补小时数，大屏接口提供 `forecast.imputed_hours`。计价与推荐要求近12小时至少8小时有记录；图表可用较稀疏数据展示趋势，但不因此获得计价资格。当前按小时样本均值估计功率，不能替代真实电表连续计量。
