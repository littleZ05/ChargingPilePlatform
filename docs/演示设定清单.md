# 演示设定清单：哪些数字和行为是预设的

核对日期：2026-09-16。依据主线代码 `5fcbcf7`，只说明实际实现，不修改账号余额。

**先记住：数据库里存了数据，不等于这些数据来自真实用户或真实电桩。** 本项目用演示数据走实际的登录、建单、扣款、统计和告警流程。

## 一、账号、余额与资料

1. **新注册用户送100元演示余额。** 手机号在当前数据库中不存在时，首次登录会自动注册、余额设为100元；不是每次登录送100元。昵称默认是“用户+手机号后4位”。
2. **已有用户读取数据库余额。** 充值、结算后余额会变化，退出重登不会恢复成100元。切换数据库或重置演示库后，若该手机号不再存在，下一次登录又属于新注册。
3. **13800138001和13800138002不是固定余额账号。** 它们没有“一个永远有钱、另一个永远没钱”的规则。旧登录提示“13800138002无余额”是写死的过时文案，已经修正。它若首次注册，也会获得100元。
4. **手机号免密登录。** 输入11位手机号，由服务器查询或注册；不发短信验证码、不接真实手机认证。这是课程需求约定。
5. **默认管理员为admin / 123456。** 普通初始化确保默认管理员存在；属于演示账号，目前密码按现有数据库规则保存，不是生产级认证实现。
6. **充值是假支付，余额是真落库。** 没有微信、支付宝或银行卡扣款。点充值后，服务器将金额加到演示钱包，退出重登仍能看到。用户界面默认填50元，允许1–10000元、两位小数；服务器业务接口允许0.01–100000元，两者范围不同，以当前入口限制为准。
7. **资料页面有历史占位默认值，但不是账号规则。** 控件初始化仍有“用户#001 / 92.50元”等旧占位值；正常登录后由服务器昵称和余额覆盖。不要把初始控件值当作账户余额或注册赠送。
8. **昵称、头像修改不是纯本地演示。** 底部“我的”→头像右侧“修改昵称”；确认后保存到服务器。头像也由服务器校验并缩放保存，换窗口重新登录可以读取。

## 二、充电和计费

9. **没有连接真实电表。** 充电中的电量由客户端每秒按“额定功率÷3600”累加；恢复未完成订单时，根据服务器记录的开始时间和额定功率估算。所以关掉客户端一段时间再恢复，估算电量可能增加。
10. **预约按钮目前表示立即建单充电。** 它不是预约未来某个时间段的独立排期系统。服务器确认建单后，订单和电桩占用状态才生效。
11. **演示电量仍需通过服务器检查。** 服务器会检查订单归属、时长、额定功率和电量范围，再按订单锁定价结算。客户端自己显示的金额不是最终扣款依据。
12. **闲时规则固定为“预测空闲率大于60%→8折”。** 使用未来1小时的简化预测；目前不是后台随意配置任意复杂营销规则。近12小时至少8小时有功率记录才能参与该定价，样本不足维持基础价。
13. **开单时锁价。** 开单后即使特惠取消，本单仍使用服务器保存的原单价。金额按元存储，结算金额和余额舍入到分。模拟支付、电量不意味着可以绕开真实的事务和扣款检查。
14. **余额不足不会自动透支。** 结算失败后保持原活动订单；充值后重试同一订单。成功写请求和回执会一起保存，重复请求不重复扣钱。

## 三、站点、历史订单与大屏

15. **独立演示入口预置5个站、37根桩、6个用户、128笔订单。** 运行 `tools/demo_5min.sh` 首次创建 `build-demo/chargingpile.db` 时写入；历史订单按脚本规则生成，日期随创建时间变化，不代表真实90天运营记录。里面包含完成、取消和进行中的订单，所以刚启动也可能已有营收或占用桩。
16. **直接启动PcServer与独立演示入口不是同一套初始数据。** 直接启动默认使用可执行文件旁的 `chargingpile.db`，站点为空时程序添加3个演示站及模拟桩；不会自动得到5站37桩128订单的完整种子库。`PCSERVER_DB_PATH` 可指定别的库。
17. **普通启动不重置演示库。** `demo_5min.sh --reset` 或 `seed_demo_data.sh` 才显式备份并重建独立演示库。重置后你后来注册的账号、充电订单和改过的昵称不会留在新库中，旧库在备份里。
18. **初始特惠、功率阈值和历史功率也是预填数据。** 种子里部分站已设8折；服务端启动后的定价引擎会按当前样本重新判断，不能要求预置特惠永远保持。
19. **大屏有离线样例。** 服务端未连接时，大屏可显示内置演示数字；底部会写离线演示。连上后才读取SQLite聚合。连接中断后保留最近快照，不代表数字仍实时更新。每10秒轮询一次，小金额KPI可能按整数显示，精确金额看订单或验收向导读数。
20. **腾讯POI的名字/地址与桩状态不是同一来源。** 未接上服务器数据时，页面可能使用本地样例或腾讯地点。腾讯POI只提供地点信息，价格、桩数、空闲数量、在线率用本地稳定算法生成占位值，不能当作充电运营商实时状态。服务器数据接入后优先使用服务器站桩和执行价。

## 四、预测、自愈与开关

21. **负荷预测是站级简化OLS/WMA模型。** 支持1/6/24小时，不是已经训练了天气、节假日、出行行为等完整多维模型。预计空闲桩数按预测功率与容量比例估算，不保证用户到站后一定有这些空桩。
22. **图表允许展示演示曲线，但演示曲线不用于自动折扣。** 历史记录不足时图表有仿真兜底并标明来源；有部分记录时缺测小时插补，标出插补小时数。实测零功率不当作缺测。
23. **远程重启是模拟维护动作。** 项目没有独立物理桩端接收重启指令；界面出现模拟重启事件不能证明重启了真实设备。有活动订单的桩不能靠重启释放。
24. **自愈按新样本推进。** 连续3条低功率样本触发预警与模拟重启；预警之后又有3条新低样本才升级故障；新正常样本解除。只反复点“立即检查”或等计时器，不会凭空生成新证据。
25. **S03-P02预置3条低功率记录。** 全新种子库用它演示告警，启动后可能自行出现预警。这不是刚刚发生的真实设备故障，也不应仅靠等待就自动升级故障。
26. **“注入功率样本”就是人为造演示数据。** 后台自愈页低样本取当前低阈值的0.5倍，正常样本取1.5倍；无阈值时改用额定功率的0.05/0.85倍。按钮会写功率记录，用来触发产品告警规则。
27. **阈值校准有固定简化规则。** 读取最近100条正功率记录，剔除已知低异常及离群值，至少6条正常样本才保存；低阈值取均值80%，高控制限由移动极差计算。当前自动告警使用低功率规则，高控制限只记录。
28. **服务计时器用于演示刷新。** 当前主程序定价和自愈服务均每10秒检查一次；不是设备每10秒真实上报。`PCSERVER_SIMULATE=1` 才额外开启旧的演示桩状态迁移，默认不启用，正式验收不要开它。`PCSERVER_AUTOLOGIN=1` 可跳过管理员登录，仅供开发/自动化场景，不能用来证明登录验证通过。

## 五、点按验收向导的两个“造场景”按钮

29. **“准备零余额演示用户”只调整13800138088。** 先在客户端登录一次该账号；若有活动订单会拒绝准备。确认后仅将独立演示库该用户余额设为0，退出重登查看。不影响13800138002，也不改变所有新用户赠送100元的规则。
30. **“准备闲时折扣场景”会修改独立演示库第一站的样本。** 只选正常、空闲、无活动订单的桩，替换这些桩无关联订单的功率记录，写入12小时额定功率20%的样本；同时将演示均值/低阈值/高阈值设为额定功率的20%/16%/24%。关联历史订单的样本和订单金额不改。向导只准备条件，8折仍要由后台定价引擎计算。
31. **“符合/不符合”是你手动观察的记录。** 向导不会根据打开了窗口就自动判通过。“读取数据”取的是演示库实际数值，但它本身也不代表全部需求通过。

## 怎么避免误判

- 看新用户：确认手机号在当前库里原本不存在，首次登录应为100元；再次登录应保留实际余额。
- 看余额不足：使用13800138088及向导零余额按钮，不相信某个手机号天然没钱。
- 看闭环：同一笔订单金额、钱包变化、后台营收增量、大屏数据一致，才证明流程联动。
- 看预测和告警：先区分种子/注入/模拟记录与真实采样，解释清楚后再演示算法结果。
- 导航已按2026-09-18产品决定收敛为仅驾车；Key配额限制仍可能让内嵌网页打不开，兜底用「在浏览器打开」，草稿PR #37已于2026-09-18关闭。
