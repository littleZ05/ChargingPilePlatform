# 创新点1：闲时“反向激励”动态计费设计（NO.22）

> 负责人：张芮萌（业务引擎/推送）；接口依赖：吴羽桐（ML 预测写库）、葛伊诺（用户端渲染）、陈庚泉（表结构）
> 规则常量：`src/common/common.h` → `cp::Pricing`

## 业务规则

1. 机器学习（简化模型）预测未来 1 小时某电站空闲率；
2. 当**预测空闲率 > 60%**（`kIdleRateThreshold`）时，系统自动把该电站充电价下调为 **8 折**（`kDiscount`）；
3. 用户端充电站卡片/电桩详情显示“闲时特惠”标签与折后价；
4. 服务器端“价格策略模拟引擎”负责规则执行与状态回写，便于演示“预测→业务动作”闭环。

## 数据流

```
ML 简化预测（吴羽桐，预留接口）
   │ 写入
   ▼
SQLite marketing_strategy（陈庚泉 schema，已建表）
   │ 读取
   ▼
服务器端价格策略引擎（张芮萌）：按 cp::Pricing 常量判定 → 更新 stations.base_price 或策略表
   │ 实时下发（Socket 推送或用户端轮询）
   ▼
充电用户端（葛伊诺）：电桩详情多查一次优惠率，特惠字体渲染
```

## 表结构对应（schema.sql 已含）

- `stations.base_price`：基础价（元/度）；
- `marketing_strategy`：`station_id / base_price / discount / rule_desc / is_active / valid_from / valid_to`；
- 查询示例（服务器端取“某站当前是否打折”）：

```sql
SELECT s.id, s.base_price, m.discount, m.rule_desc
FROM stations s
LEFT JOIN marketing_strategy m ON m.station_id = s.id AND m.is_active = 1
WHERE s.id = ?;
```

## 接口约定草案（待吴羽桐确认）

- 张芮萌引擎读取上述输出，按阈值决定 `discount`；
