# 不看代码，跟着点：图形化验收手册

## 第一次只做这三件事

1. 双击桌面 **充电桩点按验收**。如果提示不可信，右键选择“允许启动”。
2. 向导点 **启动演示窗口**，等待编译；在弹出的后台登录框输入 `admin / 123456`。
3. 用户端输入 `13800138001` 登录，再回到向导点 **打开大屏**。用 Alt+Tab 在窗口间切换。

向导左边按顺序选项目，右边会告诉你：**怎么点 → 应该看到什么 → 说明什么 → 什么不算通过**。看完在底部选择“符合/不符合/未检查”，最后导出你的验收记录。向导不会替你自动判定通过。

换电脑或桌面图标丢失：在仓库运行 `python3 tools/install_acceptance_shortcut.py`，或 `./tools/acceptance_gui.sh`。图形向导需要Ubuntu的 `python3-gi` 和 `gir1.2-gtk-3.0`；本机已具备。

## 最值得先验的三个现象

- **钱对得上**：充电前记数据，充完后本单0.80元，余额就应少0.80元，今日营收多0.80元。只弹“成功”不够。
- **关窗口不丢单**：充电时关用户端，再登录仍找得到原订单。丢了就不符合。
- **告警不是乱跳**：3条低样本→预警；反复检查不变；再3条新低样本→故障；新正常样本→恢复。

## 数据与记录在哪里

使用独立的 `build-demo/chargingpile.db`；不会改正式库。向导“准备零余额”和“准备闲时折扣”是明确的**演示条件注入**，按钮会说明改哪些数据并让你确认；它们不伪造订单结果或验收结论。请勿在保留重要业务数据的演示库上准备场景。

“记下当前数据/读取现在的数据”会弹出实际数据库读数及差值，不需要你开SQL工具。大屏小额可能四舍五入显示整数，向导和订单金额按分对照。请避免多人同时操作影响差值。

你的手动报告保存在 `build-demo/我的验收记录-日期时间.md`。导航按组长指示暂缓。线程、事务、防重试等内部机制的证据看《测试执行结果》，不能只靠窗口不卡顿就断言实现。

## 1. 先把三个窗口打开（准备）

**怎么点**：点上方【启动演示窗口】。首次编译请等一会儿，会弹出管理员登录框和用户端。
管理员输入 admin / 123456。登录后再点【打开大屏】。
三个窗口分别是：后台（管理）、用户端（充电）、浏览器大屏（统计）。用 Alt+Tab 切换。

**应该看到**：后台有十个页签，用户端有手机号登录框，大屏底部显示 SQLite 实时聚合。

**这说明**：说明程序能启动、后台服务和大屏接通了。仅启动成功不等于所有需求完成。

**不算通过的情况**：后台不弹出：点【查看启动日志】。端口被占：关闭之前的PcServer/UserClient窗口再启动；向导不会替你杀进程。大屏离线演示数字不能当作真实数据。

## 2. 登录、改昵称、换头像、充值（NO.6）

**怎么点**：用户端输入 13800138001 登录。点【我的】；记下余额。
点头像右侧【修改昵称】；点【更换头像】选择一张PNG/JPEG小图片。
点【充值】，输入10元确认。退出再用同一手机号登录。

**应该看到**：余额只增加10元；重新登录后昵称、头像、余额仍在。后台【用户管理】搜索这个手机号，余额也一致。

**这说明**：登录注册、资料保存、充值真正写入数据库，不是只改屏幕。支付为课程模拟。

**不算通过的情况**：充值按钮点了但没有成功提示不能算通过；重登后昵称恢复旧值说明资料没有持久化。

## 3. 查站、看真实电桩（NO.4）

**怎么点**：用户端点【首页】，选一个服务器充电站，打开详情；看电桩编号、类型、功率、状态。
后台【充电站管理】选同一站，对照电桩列表。

**应该看到**：两个窗口的电桩编号一致。只有空闲且健康的桩能开单；故障或占用桩不能随意充电。

**这说明**：用户端查到的是后台的真实站桩数据。按距离排序只证明当前定位下的排序，在线地址定位属于暂缓的地图验收。

**不算通过的情况**：卡片显示演示/POI时，不把模拟价格、模拟空闲数当后台数据。

## 4. 充一次电，看三处数字一起变（NO.7 / NO.9 / NO.16 / NO.22）

**怎么点**：先点向导【记下当前数据】。用户端选第一站空闲快充桩，点【预约充电】，等待30秒。
后台【电桩状态】应看到该桩充电中；用户端点【结束并结算】。
记下本单金额，切到【我的】看订单和余额；后台看【销售业绩】，大屏等10秒刷新。
再点向导【读取现在的数据】，对照之前记录。

**应该看到**：只有收到服务器确认才显示已结算。余额减少本单金额，今日营收增加同一金额，完成订单多1笔，桩释放。

**这说明**：这才是用户端→服务器→数据库→大屏的业务闭环；金额由服务器按开单时价格结算。电量仍按时长模拟。

**不算通过的情况**：大屏金额可能按整数显示，小额先看向导精确到分的读数。余额变化与营收不同，或订单未完成却显示已结算，应标【不符合】。

## 5. 关掉用户端，再找回未完成订单（NO.7 / NO.15 / NO.20）

**怎么点**：用户端再开始一单，等10秒后只关闭用户端，后台保持打开。
点向导【重开用户端】，输入原手机号。
看到恢复提示后结束结算。

**应该看到**：提示有未完成订单，自动回到该单结算；不会凭空丢单，也不能另开第二笔活动订单。

**这说明**：订单存在服务器数据库，关闭窗口不等于取消订单。重试以同一订单核实结果。

**不算通过的情况**：重新登录后可以无视旧单继续开新单、旧单丢失，都不符合。

## 6. 余额不足：不能假装结算成功（NO.7 / NO.20）

**怎么点**：使用新手机号 13800138088 登录；先完成已有订单。
点向导【准备零余额演示用户】（只调整独立演示库中的这个专用账号）。
开始一单快充，等30秒结束。失败后到【我的】充值10元，再返回充电页重试结算。

**应该看到**：第一次提示余额不足，原订单还在，界面不显示已结算；充值后同一笔订单可结算成功，只扣一次。

**这说明**：失败会回滚，不会出现扣钱但没订单、或者没扣钱却显示成功。

**不算通过的情况**：第一次失败后订单消失，或重试生成另一笔订单，应标不符合。

## 7. 后台：搜索、冻结、统计、站桩管理（NO.8–14）

**怎么点**：【用户管理】搜手机号，冻结一个没有活动订单的用户；用该用户尝试预约充电，再解冻重试。
【销售业绩】切换7天/30天；【电桩状态】看数量与比例。
【充电站管理】新增一个测试站并填写地址、坐标、桩数，点站查看明细。
有活动订单时尝试在【充电桩管理】重启或修改该桩。

**应该看到**：冻结用户不能新开单，解冻后可以。曲线可切换，新站及桩出现。活动订单的桩维护被拒绝；有历史订单的桩不能删除。

**这说明**：权限限制、统计查询、新增站点与订单保护均有实际行为。重启是模拟，不代表控制真实设备。

**不算通过的情况**：冻结仍能开单、维护后活动订单丢失，或新增只弹成功而列表没有数据，都应标不符合。

## 8. 负荷预测与低拥堵推荐（NO.17 / NO.19）

**怎么点**：后台【负荷预测】选择电站、历史窗口，依次选未来1小时、6小时、24小时；切换OLS/WMA。
看状态栏的数据来源、插补小时数、峰值与预警；快速切站，确认最后展示的是最后选的站。
用户端首页切换【距离优先】和【低拥堵推荐】。

**应该看到**：图表随选项变化，操作不应卡死。样本不足应明确提示，不编造真实预测；有预测时显示预计空闲桩数。

**这说明**：证明预测和界面联动、异常数据提示；后台线程是否真实执行由自动化线程测试提供证据，不能只凭不卡顿就下结论。模型是简化站级预测，不是天气/节假日完整AI。

**不算通过的情况**：切站后被旧结果覆盖、24小时选项没有作用、演示数据标成真实，都不符合。

## 9. 动态折扣真的影响结算（NO.22）

**怎么点**：确保没有进行中的演示订单。点向导【准备闲时折扣场景】。
后台【价格策略】点【立即重算】，看第一站是否8折（基础价×0.8）。
用户端退出并重登刷新站点，第一站应标闲时特惠。新开一单，等待30秒结算。

**应该看到**：第一站有预测依据、决策时间、折扣；用户端展示价与该单锁定价一致，最终金额约为电量×锁定单价。

**这说明**：向导只注入明确标注的演示功率样本，折扣与结算由产品计算，不由向导伪造通过结果。

**不算通过的情况**：只出现特惠徽标但仍按原价结算，不符合。已经开单后再改价，不应改变老订单锁定价。

## 10. 自愈：正常→预警→故障→恢复（NO.11 / NO.23）

**怎么点**：后台【自愈告警】选第一站S01-P02（先结束它的订单）。必要时注入正常样本使健康级别正常。
连续点3次【注入低功率样本】，看预警和事件；再点几次【立即检查】，不要注入样本。
再注入3次低功率，最后注入1次正常功率。

**应该看到**：前三次低样本触发预警和模拟重启；只反复检查不会升级；新3条低样本后升级故障；新正常样本后解除。每次状态变化有事件记录。

**这说明**：告警依赖新证据，不是每10秒随机改状态。恢复和重启是课程模拟运维，不是物理桩指令。

**不算通过的情况**：没新样本也升级、故障仍可开单、事件与健康状态矛盾，都不符合。

## 11. 错误提示、自检与自动测试证据（NO.15 / NO.18 / NO.20 / NO.21）

**怎么点**：登录输入短手机号、新增站输入不合法坐标，观察是否拒绝且程序不崩溃。
后台【运行日志】看错误；【交付自检】运行检查。
点向导【打开测试报告】。最后在每个步骤选择符合/不符合/未检查，再【导出我的验收记录】。

**应该看到**：非法输入有清楚提示，自检能说明哪些服务可用。导出报告只包含你亲自标记的结果，不自动把未检查项写成通过。

**这说明**：可见操作配合自动化测试，才能判断需求覆盖。PR/版本管理（NO.1–3）和线程/事务细节应看测试报告及交付核对，不能靠点窗口全部证明。

**不算通过的情况**：自检通过不等于所有23项通过；导航已按组长要求暂缓，始终单列为未验收。
