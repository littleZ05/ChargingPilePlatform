# 评审检查单（NO.21，负责人：张芮萌）

> 用途：PR 合入前 / 阶段评审时逐项打勾，组长作为 PR review 依据。

## A. PR / 代码评审（每次合入 main 前）

**A1 可编译与产物**
- [ ] `qmake6 && make`（或项目声明的构建方式）在本机通过
- [ ] 程序可启动，核心路径无崩溃
- [ ] `git status` 无构建产物/临时文件（Makefile、*.o、moc_*、ui_*.h、可执行文件等）
- [ ] 提交信息格式 `[模块名] 简述`，中文说明做了什么

**A2 代码质量**
- [ ] 命名与缩进符合编码规范（见 docs/04/05/06 编码规范）
- [ ] 没有魔法数字散落（需常量化的已放入 common 或模块常量）
- [ ] 错误处理统一走 error_utils / error_notify（NO.20）
- [ ] 数据库访问使用参数绑定，禁止字符串拼 SQL
- [ ] 注释解释了“为什么”，不只抄代码

**A3 需求对应**
- [ ] PR 描述注明完成的需求 NO. 与功能点
- [ ] 与需求矩阵描述一致，未悄悄扩大/缩小范围
- [ ] 涉及公共契约（schema/common）的改动已先在群里说明并获同意
