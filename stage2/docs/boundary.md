# 边界声明：本项目做了什么、没做什么

答辩与提交材料中必须与本文件保持一致。原则是**只声明真实运行过的内容**，未部署的组件给出等价实现与迁移路径，不用"已构建大数据平台"这类超出证据的表述。

## 一、真实运行的组件

| 组件 | 证据 |
|---|---|
| Python 3.10 标准库（无第三方依赖） | `stage2/*/**.py`，全部可 `python3` 直接运行 |
| SQLite（业务库读取 + 数仓落库 + 即席查询） | `build-demo/chargingpile.db`、`warehouse.db`（49 张表，含预测层回落的 DWS/ADS） |

| Vue3 + ECharts 离线大屏 | `stage2/dashboard/web/`（源码）与 `web/dist/`（构建产物，ECharts 按需打包，无 CDN、无外网依赖） |
| 自研算法实现 | K-Means（k-means++）、最小二乘回归、岭回归（手写高斯消元）、分位数回归（pinball loss + IRLS）、Pearson、IQR/3σ、季节基线、扩展窗口滚动评估 |
| 自动化测试 | 清洗 7 项 + 采集 6 项 + 分析 7 项 + 预测 98 项 + 大屏 17 项（其中 2 项 HTTP 用例需能访问 127.0.0.1：代理环境下用 `env -u LD_PRELOAD` 复跑） |

## 三、数据使用边界（不可越界表述）

1. `chargingFees` 原字段合计 401.52，**币种与语义未核实**，不得称为营收、收入或利润。
2. 会话年份原始值为 `0014`/`0015`，**不得改写为 2014/2015**，也不做真实日/月/年趋势；小时与星期来自源字段校验通过的行。
3. `session_count` 是**会话次数**，不是充电桩数量，也不能等同成功支付订单数。
4. 零电量（55 条）与零费用（3016 条）**保留并标记**，不认定失败、免费或缺失。
5. 峰谷时段划分与分时电价（高峰 1.5 / 平时 1.0 / 低谷 0.7 元/kWh）是**项目设定的取值假设**，
   由此派生的 `estimated_fee` **不是真实收费、不是营收**，必须与原费用字段分列呈现、不相加。
   老师原始材料（说明会 PPT、清洗讲义、交付清单）中检索不到任何电价数字，展示层**不得写成老师原始材料中的数字**。
6. 桩类型中文标签（直流 / 交流 / 直交流一体）是**假设映射**；数据集里的编码 4 无对应标签，
   保留原编码并标注「待核编码4」，不并入任何一类、不猜语义。
7. 电池表 `dsv13r2` 与会话表 `nvv2t` 的 ID 数值重合**不构成业务关联**，不做 JOIN；电池时间精度不可恢复，不做时间序列。
8. 课程数据集为郑州站点，**与第一阶段 Qt 演示站（北京）不是同一批站点**，两组数据不做合并统计。
9. 采集到的平台侧数据（订单 128 条、设备功率 42 条、告警 1 条）是**课程演示库**，其规模不代表真实生产量级。

## 四、模型边界

- 年份字段不可信，时间轴由 `created_raw` 的月日构造并与 weekday 逐行自洽校验，对外只用相对天数描述，不声称真实日历日期。
- 负荷预测覆盖会话数与电量的未来 1/6/24 小时；方法选择只看前 70% 测试日，指标只报后 30%。只有 24 小时跨度上线岭回归（报告集相对最佳基线 +8%），1/6 小时跨度的小优势不成立，直接上线基线。
- 单次充电分位数（时长/电量的 P10/P50/P90）按"每 30 天重训一次、用最近 90 天窗口"评估，并核对经验覆盖率；模型 6 个格子整体更低，但只有电量 P10 达到 10% 采纳门槛，其余上线经验分位数。
- 指标**如实呈现**：基线胜出的格子就写基线胜出，不宣称高精度，也不用于产能承诺。
- 站点画像聚类（7 维行为特征，k 由轮廓系数在 2..6 之间择优）与繁忙度分档（活跃日日均会话数分位数）只描述站点行为；会话数不足 20 次的站点标注为稀疏、不参与聚类。该结果不代表经营优先级或因果结论。
