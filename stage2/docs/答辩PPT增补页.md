## 第 1 页：第二阶段目标与交付范围

- 必做：多维度数据分析与 Web 可视化大屏；预测按课程为选做，本轮补齐为轻量可评估模型。
- 数据来源：课程三份 CSV（会话 3395、站点 105、电池 1594）+ 第一阶段平台数据库与运行日志。
- 一句话：把课程数据变成"可追溯、可复现、可演示"的分析链路。

## 第 2 页：整体架构（七大环节）

- 图：`docs/architecture.md` 的数据流图（可截屏或重画为横向流程）。
- 文字：采集 → 清洗 → 分层存储 → 分析 → 预测 → 大屏与接口。
- 强调：每个环节都有产物与校验，不覆盖旧证据。

## 第 3 页：技术栈映射与边界（答辩重点页）

- 环境实况：2 核 / 7.9 GB，无 JDK、无 Hadoop/Spark/Kafka/Hive、无 Docker、无 root、外网受限。
- 映射表：Sqoop/Flume/CDC → 采集适配器；Spark SQL → 清洗规则脚本；HDFS/Hive → 分层目录 + SQLite 数仓；Kafka/Flink → 事件回放 + 滚动窗口；MLlib → 标准库算法。
- 结论句："我们没有宣称部署集群，而是给出可运行的等价实现与迁移路径。"

## 第 6 页：多维度分析结论

- 五维聚合：站点、设施编码、平台、开始小时、星期（大屏可交互）。
- 高峰：11 点 504 次、12 点 475 次、17 点 437 次；星期以周四 735 次最高。
- 相关与回归：时长-电量 r = 0.316，弱相关，如实呈现。
- 配图：`06-小时会话次数.png`、`09-站点前十会话.png`。

## 第 7 页：预测与模型评估

- 方法：星期×小时季节基线 + 线性回归；留一星期交叉验证。
- 结果：基线 MAE 12.65 优于回归 20.78，模型自动选择基线。
- 用途：低拥堵时段推荐、运营参考；不承诺精度、不做真实日历预测。

## 附：答辩预设问答

| 可能的问题 | 回答要点 |
|---|---|
| 为什么没有用 Spark/Hadoop？ | 本机 2 核无 JDK、无外网无 root，无法部署；我们用等价实现完成同样的分层与算法，并给出迁移路径（PPT 第 3 页）。 |
| 数据量这么小算大数据吗？ | 课程数据是 3395 会话级；我们的价值在链路完整与数据可追溯，不虚称 TB 级或集群性能。 |
| 零费用为什么不算异常？ | 没有证据表明是免费还是漏记，保留并标记，避免编造营收。 |
| 预测精度为什么这么低？ | 年份不可信，只能用星期×小时，每格 7 个样本；我们如实报告 MAE，不夸大。 |
| 和第一阶段什么关系？ | 同主题、同平台数据，但两套站点范围不同（北京演示站 vs 郑州课程数据集），只做同源只读引用，不合并统计。 |
