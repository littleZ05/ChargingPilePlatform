## 第 3 页：技术栈映射与边界（答辩重点页）

- 环境实况：2 核 / 7.9 GB，无 JDK、无 Hadoop/Spark/Kafka/Hive、无 Docker、无 root、外网受限。
- 映射表：Sqoop/Flume/CDC → 采集适配器；Spark SQL → 清洗规则脚本；HDFS/Hive → 分层目录 + SQLite 数仓；Kafka/Flink → 事件回放 + 滚动窗口；MLlib → 标准库算法。
- 结论句："我们没有宣称部署集群，而是给出可运行的等价实现与迁移路径。"

## 第 7 页：预测与模型评估（2026-09-18 按重构后的模型改写）

- 时间轴：源年份不可信，按 `created_raw` 的月日构造相对天数；321 天里 238 天有采集、83 天空白，空白日掩码排除，不当零。
- 方法：扩展窗口滚动前进（前 70% 测试日选方法、后 30% 只报告），候选为全局均值、季节 naive、四周移动平均、岭回归（小时/星期哑变量 + 滞后特征）。
- 结果：未来 24 小时的会话数与电量由岭回归上线，报告集 MAE 5.89 / 32.90，比季节 naive 基线分别低 8.1% / 8.8%；1 小时与 6 小时跨度未过 10% 采纳门槛，如实上线更简单的基线。
- 单次充电：时长与电量的 P10/P50/P90 分位数；6 个格子都优于经验分位数基线，只有电量 P10 领先 13.8% 达到门槛，其余上线可直接查表的分位数。
- 站点画像：k=2（轮廓系数 0.6414），56/105 个站点参与聚类，前 70%/后 30% 分半一致率 0.9189；繁忙度另按分位数切 4 档，稀疏站点只标注不归类。
- 用途：运营参考与低拥堵时段推荐；不承诺精度、不做真实日历预测。

## 附：答辩预设问答

| 可能的问题 | 回答要点 |
|---|---|
| 为什么没有用 Spark/Hadoop？ | 本机 2 核无 JDK、无外网无 root，无法部署；我们用等价实现完成同样的分层与算法，并给出迁移路径（PPT 第 3 页）。 |
| 数据量这么小算大数据吗？ | 课程数据是 3395 会话级；我们的价值在链路完整与数据可追溯，不虚称 TB 级或集群性能。 |
| 零费用为什么不算异常？ | 没有证据表明是免费还是漏记，保留并标记，避免编造营收。 |
| 预测精度为什么只能到这个水平？ | 源年份不可信，只能用相对天数与滞后特征；我们给了滚动评估、基线和采纳门槛，没达门槛的跨度就上线基线，不夸大。 |
| 和第一阶段什么关系？ | 同主题、同平台数据，但两套站点范围不同（北京演示站 vs 郑州课程数据集），只做同源只读引用，不合并统计。 |

### 机器学习部分（P1–P4 全部落地，2026-09-18）

预测不再是一条"星期×小时基线"，而是一套可评估、可服务、可落库的模型层，顺序是先算法落地、再存储与大屏。

| 阶段 | 交付 | 关键数字 |
|---|---|---|
| P0 | 相对时间轴 + 缺测掩码 + 基线 | 321 天（238 有采集 / 83 空白），空白日掩码排除 |
| P1 | 滞后特征负荷预测（会话数/电量 × 未来 1/6/24 小时） | 24 小时跨度岭回归上线：会话 5.8862 对 6.4021、电量 32.8986 对 36.0547 |
| P2 | 单次充电时长/电量分位数（P10/P50/P90） | 6 个格子全部优于经验分位数基线，电量 P10 领先 13.8% |
| P3 | 站点画像聚类 + 繁忙度分档 | k=2，轮廓系数 0.6414，分半一致率 0.9189，高 15 / 较高 23 / 较低 18 / 样本不足 49 |
| P4 | 预测服务 + 大屏预测视图 + 预测结果落库 | 5 张表回落数仓（`dws_day_hour` 7704、`dws_station_features` 105、`ads_station_busyness` 105、`ads_forecast` 144、`ads_session_quantile` 1728） |

完整指标、候选方法与限制见 `stage2/docs/预测评估_v2.md`（模型卡，随训练产物一起生成）。
