## 一、数据清洗

### 1. 老师总体要求

从七阶段总纲看，数据清洗阶段要求：去重、缺失值处理、异常值处理、噪声过滤、一致性校验，以及字段标准化、单位统一、编码转换，最后产出数据质量报告。

针对 EV 充电数据，老师还点名了几条具体业务口径（扣分点，必须覆盖）：

1. **桩类型转换**：`case when` 把 `facilityType` 的 1/2/3 转成「直流 / 交流 / 直交流一体」；
2. **时段划分**：按开始时间分**高峰（8-11点、18-21点）、平时（12-17点）、低谷（0-7点、22-23点）**；
3. **电价计算**：**高峰 1.5 元、平时 1 元、低谷 0.3-0.7 元**，算总费用；
4. **异常值过滤**：充放电电流超出 -40~40 视为异常，最高温度不超过 85 度；
5. **数据聚合**：`groupBy` 对桩类型分组统计总充电量和使用频次；
6. **写 CSV 必须 `header=True`** 保留列名。

### 2. 工具分工

| 清洗子任务 | 工具/方法 |
|---|---|
| 读取原始 CSV（保留列名） | `spark.read.csv(..., header=True)` |
| 列名规范化 | `StructType` 定义列名与类型 / `withColumnRenamed` |
| 桩类型 1/2/3 转文字 | `case when`（`when().otherwise()`） |
| 时段划分 | `case when` 按 `start_time` 判断 |
| 电价计算 | `withColumn` 派生字段：电量 × 时段单价 |
| 异常值过滤 | `filter` + 阈值条件（电流/温度） |
| 桩类型聚合 | `groupBy("facility_label").agg(sum/count/avg)` |
| 落盘 | `df.write.csv(..., header=True)` |
| 质量报告 | 对账清单 + 规则命中计数 |

一句话：以 **PySpark** 为清洗主引擎，`case when` 做特征工程、`groupBy` 做聚合、`header=True` 落盘，配合质量报告完成整条清洗。

## 二、数据分析（特征提取）

### 1. 做了什么

- **站点画像特征**（聚类用）：每站 4 个特征——会话数、总电量、平均充电时长、零电量占比，z-score 标准化；
- **预测特征**（回归用）：小时、是否周末、星期索引；季节基线用「小时画像 × 星期系数」；
- **聚类**：K-Means，k-means++ 初始化、固定随机种子（结果可复现），105 站点聚 3 类；
- **预测建模**：季节基线 vs 多元线性回归（`会话量 ≈ b0 + b1·小时 + b2·是否周末 + b3·星期索引`），留一星期交叉验证（7 折）择优。

### 2. 结果

**聚类（3 类站点画像）**

| 簇 | 站点数 | 会话数 | 累计电量 | 平均会话/站 | 画像 |
|---|---:|---:|---:|---:|---|
| 0 | 77 | 3007 | 17132.7 kWh | 39.05 | 高活跃主力站点 |
| 1 | 4 | 35 | 112.12 kWh | 8.75 | 冷门/低活跃站点 |
| 2 | 24 | 353 | 2478.87 kWh | 14.71 | 中等活跃站点 |

**相关性与回归**

- 时长与电量 Pearson 相关系数 = **0.316**（弱正相关）；
- 一元回归：`电量 ≈ 0.607 × 时长 + 4.086`，R² = 0.0999，样本 3395；
- 结论：时长不是决定电量的主导因素（还受车型功率、桩类型等未观测变量影响）。

**季节性**

- 小时峰值：11 点(504)、12 点(475)、17 点(437)；
- 星期峰值：周四(735)、周三(713)、周二(635)；
- 星期系数：工作日 1.2~1.5，周六 0.13、周日 0.05 → 周末充电量断崖式下跌。

### 3. 工具

分析引擎 **PySpark（Spark SQL / MLlib）**；聚类 **K-Means（k-means++）**；回归 **OLS 最小二乘**；相关性 **Pearson**；时序 **季节基线**；评估 **留一星期交叉验证 + MAE/RMSE/R²/相对误差**。

## 三、机器学习预测与检验

### 1. 做了什么

用「星期 × 小时」建模小时级会话量预测（源年份未证实，不做真实日历预测），对比两种方法并择优：

- **季节基线**：小时画像 × 星期系数；
- **多元线性回归**：截距 + hour + is_weekend + weekday_index；
- 评估：**留一星期交叉验证（7 折，168 个建模单元）**。

### 2. 检验结果

| 方法 | MAE | RMSE | R² | 相对误差 |
|---|---:|---:|---:|---:|
| **季节基线（选中）** | **12.65** | **22.29** | **0.474** | **0.626** |
| 线性回归 | 20.78 | 27.81 | 0.181 | 1.028 |

- 季节基线在 MAE / RMSE / R² 上全面优于线性回归，选为最终模型；
- 说明充电需求主要由「星期 × 小时」的周期性主导，而非简单线性趋势；
- 每次会话平均电量 5.81 kWh，用于电量预测换算。

> 应对「准确率」：预测目标是连续值（会话量），属回归任务，正确指标是 MAE/RMSE/R²/相对误差；「准确率」是分类指标，此处不适用。

### 3. 工具

**PySpark（Spark MLlib）**；算法：**季节基线（时序）+ 线性回归（OLS）**；评估：**留一星期交叉验证（7 折）+ MAE / RMSE / R² / 相对误差**。

## 收尾一句话（整段）

*"特征上，站点侧抽会话数/总电量/平均时长/零电量占比做 K-Means 聚类，时序侧用星期×小时建模；结果上，105 个站点分成高/中/低三类活跃画像，季节基线模型经 7 折交叉验证 MAE=12.65、R²=0.474，明显优于线性回归，说明充电需求是周期主导。"*

## 四、为什么选这几个分析方法（方法 → 作用）

> 核心逻辑：方法是为「分析目标」服务的——先定想回答什么问题，再选能回答它的方法。

| 分析方法 | 想回答的问题（目标） | 为什么选它 | 得到的作用/结论 |
|---|---|---|---|
| 描述统计（均值/中位数/分位数/标准差） | 数据整体长什么样 | 分析起点，先摸清分布和有无极端值 | 平均电量 5.8 kWh、时长 2.9 小时；看均值 vs 中位数差异判断偏态 |
| Pearson 相关 | 时长和电量有没有关系 | 最直观的线性相关度量，且老师要求关联分析 | r=0.316 → 弱正相关：充得久一般充得多，但不是强线性 |
| 一元线性回归（OLS） | 时长每加 1 小时，电量大约加多少 | 在相关基础上量化关系，并算 R² 看解释力 | 电量≈0.607×时长+4.086，R²=0.0999 → 时长只解释约 10% 电量 |
| K-Means 聚类 | 105 个站点怎么分群，谁活跃谁冷门 | 站点太多逐个看不现实；总体要求明确列 K-Means | 3 类画像：77 高活跃主力站 / 24 中等站 / 4 冷门站 |
| 季节性指数（小时/星期） | 什么时候充电高峰、哪天人多 | 充电是周期性行为，也是预测模型的特征基础 | 小时峰值 11/12/17 点，星期峰值周三四二，周末断崖下跌 |
| IQR / 3σ 异常检测 | 数据里有没有极端值 | 老师要求异常值处理，极端值会带偏均值等统计 | 标记异常（保留不删），保证结论不被天价电量带偏 |
| 工作日 vs 周末对比 | 两类日子充电差异多大 | 老师硬性要求"必须数据对比" | 周末日均会话只有工作日 6.5%，但单次平均电量高 16% → "周末量少但充得满" |
| 峰谷/设施/平台维度分布 | 不同维度下的结构构成 | 老师要求"≥8 维度"，多角度切分看结构 | 直交流一体 1832 次居首、高峰+平时占绝大多数、iOS 多于 Android |
| 季节基线（预测） | 未来某小时会来多少车 | 充电需求是"星期×小时"的周期性，季节基线正好刻画周期 | MAE=12.65、R²=0.474，优于线性回归，作为最终模型 |
| 留一星期交叉验证 | 模型到底准不准、稳不稳 | 样本只有 7 天，留一星期利用数据更充分、防过拟合 | 得到可靠的 MAE/RMSE/R² 对比，证明季节基线更优 |

> 一句话：*"不是为用算法而用算法，而是每个方法对应一个分析目标：描述统计摸清整体、相关和回归看变量关系、K-Means 给站点分群、季节性找周期、异常检测保证结论稳健、工作日周末对比满足对比性要求、季节基线做预测，最后用留一星期交叉验证客观评估模型。"*
